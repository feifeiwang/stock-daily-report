| A20 | 全天区间想覆盖"开盘区间上限"，发现创业板怎么排都超 1.5pct | 开盘区间宽还有一条**隐性硬校验 ≤ 昨收 1.0%**（SKILL 口径没写，脚本 `build_charts.py` 有）；且全天区间必须**同时完整包含**开盘与收盘区间，三者互相挤压 | 排区间的顺序：先定收盘区间（≤1%），再定开盘区间（≤1%，且与收盘区间并集 ≤1.5%），最后全天区间取两者的并集微扩。数值排好后先跑 build_charts 让脚本校验，不要心算 |
| A21 | `build_charts` 报 `SyntaxError: invalid syntax. Perhaps you forgot a comma?` 指向某条 NEWS 文案 | **`NEWS*_D` 在模板里外层是双引号** `("{{NEWS1_T}}", "{{NEWS1_D}}")`，值里再出现 `"` （如 `<span class="hl">`）就会把 Python 字面量截断；`_T`、`OTHER*`、`BRIEF*`、`*_FOCUS` 是单引号或 HTML 列表，不受影响 | **`NEWS*_D` 里禁止出现半角双引号**（`<span class="hl">` 只允许写在 `NEWS*_T` 里）。出图前先跑一次自检：`python3 -c "import json;d=json.load(open('day.json'));print([k for k,v in d.items() if isinstance(v,str) and '\"' in v])"`，只允许 `NEWS*_T` 命中 |
| A22 | 图1 里恒科"开准收偏"却标成绿色 ✓，与上证"开收皆偏"同为部分准确却颜色不一致 | 模板颜色只认 `*_TAG`，**`*_TAG_TXT` 只是文案**，忘改 TAG 就会出现"文案=偏、颜色=准" | 改复盘结论时**同时改两个字段**：`{p}_TAG`（决定颜色）与 `{p}_TAG_TXT`（显示文案）。规则：四项都准才 `tag-ok`；开/收中任一只是"方向对但出区间"→ `tag-half`；方向相反 → `tag-bad` |
| A23 | 沙箱重建后 `/root/.codebuddy/skills/stock-daily-forecast` 整个丢失，但本次仍能全流程跑通 | 技能本体没做持久化，**唯一可靠的副本在 GitHub 仓库根**（`SKILL.md` / `scripts/` / `templates/` / `references/`） | **每天开工第一步一律 `git clone` 仓库**，从仓库里取脚本与模板（仓库即"活技能"）。本地产物目录丢了无所谓，GitHub 才是真身。若哪天 `SKILL.md` 也不在仓库里，先按本 runbook 重建再干活 |
| A24 | `gh_sync.py push` 显示 `[same] xxx 未变化，跳过`，随后 `[FAIL] md5 不一致`，但两边字节数完全相同 | `put_one()` **只比较 size** 就判"未变化"。把模板里的双引号换成单引号属于"等长改写"，被误判为无变化而不上传，回验自然对不上 | 已改为**比较远端 blob 的 md5**。教训：**"跳过"类优化一律用内容哈希，不要用 size**；看到 `[same]` 紧跟 `[FAIL] md5` 就说明命中了这个坑 |

## 二、模板与脚本清单（"改数字就能出图"）
